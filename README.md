# Selim Finance — القوائم المالية والزكاة

تطبيق ويب (PWA) لبناء القوائم المالية وحساب الزكاة من ميزان المراجعة.
React + Firebase (مصادقة + Firestore).

---

## ⚠ اقرأ ده الأول: طريقة التعديل اتغيّرت

قبل كده كان الكود كله جوّه `index.html` وبابل بيترجمه في متصفح كل مستخدم.
دلوقتي فيه خطوة بناء.

| الملف | إيه هو |
|---|---|
| **`app.src.jsx`** | 👈 كود الواجهة. |
| **`src/calc.js`** | 👈 دوال الحساب (القوائم، التصنيف، قراءة الأرقام). |
| **`src/parse.js`** | 👈 قراءة ملفات الإكسل وحساب الزكاة. |
| `tests/` | اختبارات الدوال دي. |
| `app.js` | مُولَّد تلقائيًا من الاتنين فوق. **متعدلوش**. |
| `vendor/` | المكتبات (React، فايربيز، xlsx). مُولَّدة من `node_modules` وقت البناء. **متعدلهاش**. |
| `index.html` | قشرة بسيطة بتحمّل `vendor/` و`app.js`. |
| `sw.js` | Service Worker — بيخلّي التطبيق يفتح من غير إنترنت. |
| `firestore.rules` | قواعد أمان Firestore. **لازم تتنشر يدويًا** (تفاصيل تحت). |
| `build.mjs` | سكربت البناء. |

### خطوات التعديل والنشر

```bash
npm install        # مرة واحدة بس
# ... عدّل في app.src.jsx أو src/calc.js ...
npm test           # 61 اختبار على دوال الحساب وقراءة الإكسل
npm run build      # بيولّد app.js و vendor/ ويحدّث رقم النسخة
```

أو `npm run check` = اختبار + بناء في أمر واحد.

بعدين ارفع:

```
index.html   app.js   sw.js   manifest.json   icon-192.png   icon-512.png   vendor/
```

**مهم:** لو رفعت المصدر من غير ما تشغّل `npm run build`، التطبيق المنشور هيفضل
على الكود القديم — لأن المتصفح بيقرأ `app.js` مش المصدر. فيه فحص في CI بيمنع ده.

### رقم النسخة

مصدره الوحيد `APP_VERSION` في `app.src.jsx`. غيّره هناك بس، و`npm run build`
هيوزّعه على `index.html` و`sw.js` لوحده. الرقم ده هو اللي بيخلّي المستخدمين
ياخدوا النسخة الجديدة بدل القديمة المخزّنة.

## قواعد الأمان — منشورة ومؤتمتة

القواعد في `firestore.rules` **منشورة على المشروع**، وأي تعديل عليها بينشر
تلقائيًا عن طريق `.github/workflows/deploy-rules.yml` أول ما يوصل `main`.

فمش محتاج تعمل حاجة يدوي: عدّل الملف، اعمل push، وخلاص.

تقدر كمان تشغّله بإيدك من تبويب **Actions** ← «نشر قواعد Firestore» ← Run workflow.

**قبل كل نشرة** الوركفلو بيشغّل `firebase deploy --dry-run` — فلو القواعد فيها
غلط إملائي بيفشل هناك من غير ما يلمس المشروع، بدل ما ينشر قواعد مكسورة
ويقفل التطبيق على المستخدمين.

## تفعيل البريد الإلكتروني

التطبيق بقى يبعت رسالة تفعيل تلقائيًا عند إنشاء أي حساب، وبيعرض شريط تنبيه
لأي مستخدم بريده مش مفعّل.

**الدخول لسه مسموح لغير المفعّلين عن قصد** — قفله دلوقتي معناه إن كل المستخدمين
الحاليين يتقفل عليهم فجأة.

**الخطوة الجاية (لما الكل يفعّل):** شيل التعليق عن السطر ده في `firestore.rules`
عشان القفل يبقى على السيرفر مش الواجهة بس:

```
&& request.auth.token.email_verified == true
```

## العمل من غير إنترنت

`sw.js` بيخزّن قشرة التطبيق ومجلد `vendor/` كله من **أول زيارة**، فالتطبيق
بيفتح من غير نت. البيانات نفسها (Firestore) محتاجة نت طبعًا.

المكتبات كلها مستضافة محليًا في `vendor/` — مفيش أي اعتماد على CDN خارجي.
يعني مفيش نسخة بتتغيّر من تحتينا، ومفيش داعي لـ SRI، والأوفلاين مضمون
من غير ما يستنى وصول طرف تالت.

الاستراتيجية: **الشبكة أولاً** لملفات التطبيق — يعني وانت أونلاين بتاخد آخر
نسخة دايمًا. ده مقصود: في تطبيق محاسبي، مستخدم شغّال على كود قديم فيه خطأ
حسابي اتصلّح خلاص = أرقام غلط وهو مش واخد باله.

زر «تحديث التطبيق» في الواجهة بيمسح الكاش **ويلغي تسجيل الـ Service Worker**
قبل إعادة التحميل.

## الاختبارات

```bash
npm test
```

٦١ اختبار بتغطّي:
- **قراءة ملفات الإكسل** — اكتشاف الأعمدة، الصيغة المسطّحة وصيغة الشجرة،
  استبعاد الحسابات التجميعية، فصل العملاء والموردين.
- **قراءة الأرقام** — الأرقام الهندية، الفواصل العربية، السالب بالأقواس.
- **التصنيف** — توحيد الإملاء العربي، التخمين من طبيعة الرصيد.
- **القوائم** — قائمة الدخل والمركز المالي والتجميع السنوي، بميزان كامل
  بأرقام محسوبة يدويًا.
- **الزكاة** — توزيعها على الشركاء، النصاب، وتناسب الحول.

فيه CI على GitHub بيشغّل الاختبارات وبيتأكد إن `app.js` و`vendor/` متطابقين
مع المصدر في كل push.
